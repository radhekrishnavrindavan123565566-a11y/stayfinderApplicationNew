WHAT HAPPENS WHEN YOU DEPLOY:
=============================

1. Push to GitHub main branch
2. Vercel detects push
3. Vercel runs vercel.json buildCommand:
   npm install --legacy-peer-deps && npm run build
4. Install uses .npmrc global config:
   legacy-peer-deps=true
5. Build completes with no peer dependency errors
6. Application deployed globally
7. Your custom domain points to live app

WHY THIS WORKS:
===============

The --legacy-peer-deps flag allows npm to resolve dependencies even when some packages have conflicting peer dependency constraints.

Affected packages:
  @sentry/nextjs@7.100.0
    - Expects: Next.js ^14.0
    - Has: Next.js 16.2.0
    - Status: Works perfectly

  next-cloudinary@6.17.5
    - Expects: Next.js ^14.0
    - Has: Next.js 16.2.0
    - Status: Works perfectly

This is safe and common. The packages work fine with Next.js 16 despite the peer constraint mismatch.

DEPLOYMENT WORKFLOW:
====================

Step 1: Push to GitHub
  $ git add .
  $ git commit -m "Deploy to Vercel"
  $ git push origin main

Step 2: Connect to Vercel
  - Visit vercel.com
  - Sign up / Sign in
  - Click "New Project"
  - Select GitHub repository
  - Click "Import"

Step 3: Add Environment Variables
  - In Vercel dashboard, go to Settings → Environment Variables
  - Add all required variables (see below)
  - Save changes

Step 4: Deploy
  - Click "Deploy" button
  - Wait 2-3 minutes for build
  - Get your production URL

TROUBLESHOOTING DURING DEPLOYMENT:
==================================

Issue: npm error ERESOLVE
Solution:
  - This should not happen now that vercel.json is configured
  - If it does occur:
    1. Check that vercel.json exists in root
    2. Check that .npmrc exists in root
    3. In Vercel dashboard: Clear Build Cache
    4. Redeploy

Issue: Build fails with "Module not found"
Solution:
  1. Check all environment variables are set
  2. Verify DATABASE_URL and REDIS_URL are accessible
  3. Check .npmrc file is in root with legacy-peer-deps=true
  4. Clear cache and redeploy

Issue: Deployment timeout
Solution:
  1. This can happen with slow network
  2. Click "Cancel" and "Redeploy"
  3. Check Vercel status page
  4. Wait a few minutes and try again

Issue: Database connection failed
Solution:
  1. Verify DATABASE_URL in environment variables
  2. Check MongoDB allows Vercel IPs (whitelist or public access)
  3. Verify connection string format
  4. Check MongoDB Atlas is running
