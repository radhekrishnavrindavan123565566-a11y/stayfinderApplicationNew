================================================================================
COMPREHENSIVE TESTING GUIDE - ALL INTEGRATIONS & FEATURES
================================================================================

This guide provides step-by-step instructions to test all functionality
in the StayFinder application.

================================================================================
SECTION 1: SETUP & PREREQUISITES
================================================================================

1.1 INSTALL DEPENDENCIES
─────────────────────────
npm install

Expected: All packages installed without errors
Check: npm list @sentry/nextjs googleapis


1.2 VERIFY ENVIRONMENT VARIABLES
─────────────────────────────────
Copy .env.example to .env.local:
  cp .env.example .env.local

Check current file:
  cat .env.local (or open in editor)

You should see all the environment variable templates.


1.3 BUILD THE PROJECT
──────────────────────
npm run build

Expected: Build completes successfully with "Compiled successfully" message
Check: .next directory exists


1.4 START DEVELOPMENT SERVER
──────────────────────────────
npm run dev

Expected: Server starts on http://localhost:3000
Check: No TypeScript errors in terminal


================================================================================
SECTION 2: CORE FUNCTIONALITY TESTING
================================================================================

2.1 DATABASE CONNECTION
────────────────────────
Test Endpoint: GET http://localhost:3000/api/health (if available)

Manual Test:
  1. Open MongoDB Compass
  2. Connect to MONGODB_URI
  3. Check if stayerra database exists
  4. Look for collections: users, bookings, properties, etc.

Expected: Database is accessible and has collections


2.2 AUTHENTICATION
──────────────────
Test User Registration:
  1. Open Postman
  2. POST http://localhost:3000/api/auth/register
  3. Body (JSON):
     {
       "username": "testuser",
       "email": "test@example.com",
       "password": "Password123!",
       "role": "tenant"
     }

Expected Response:
  - Status: 201
  - Response contains user, accessToken, refreshToken
  - Cookies set: accessToken, refreshToken

Test User Login:
  1. POST http://localhost:3000/api/auth/login
  2. Body (JSON):
     {
       "email": "test@example.com",
       "password": "Password123!"
     }

Expected Response:
  - Status: 200
  - Response contains accessToken, refreshToken
  - Cookies set


2.3 RATE LIMITING
──────────────────
Test Rate Limit on Login:
  1. Make 6 quick login attempts with wrong password
  2. On 6th attempt:

Expected Response:
  - Status: 429 (Too Many Requests)
  - Message: "Too many login attempts. Please try again later."


================================================================================
SECTION 3: INTEGRATION TESTING
================================================================================

3.1 CALENDAR BOOKING (Google Calendar)
───────────────────────────────────────

Step 1: Setup Google Calendar
  1. Get credentials from Google Cloud Console
  2. Set in .env.local:
     GOOGLE_CALENDAR_PROJECT_ID=xxx
     GOOGLE_CALENDAR_CLIENT_EMAIL=xxx@iam.gserviceaccount.com
     GOOGLE_CALENDAR_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\n...\n-----END
     GOOGLE_CALENDAR_ID=xxx@gmail.com
     TIMEZONE=UTC

Step 2: Test Calendar Event Creation
  1. First create a booking (see booking creation test)
  2. POST http://localhost:3000/api/integrations/calendar/create
  3. Headers: Authorization: Bearer [your-token]
  4. Body:
     {
       "bookingId": "[booking-id]",
       "title": "Property Viewing",
       "description": "Test viewing",
       "attendees": ["owner@example.com", "tenant@example.com"],
       "includeLink": true
     }

Expected Response:
  - Status: 201
  - Response contains:
    {
      "success": true,
      "calendarEvent": {
        "eventId": "...",
        "eventUrl": "https://...",
        "calendarLink": "https://calendar.google.com/..."
      }
    }

Step 3: Verify in Google Calendar
  1. Go to Google Calendar
  2. Find the event "Property Viewing"
  3. Check attendees and description

Expected: Event appears in calendar with all details


3.2 VIDEO CALLS (Daily.co - Easiest to test)
──────────────────────────────────────────────

Step 1: Setup Daily.co
  1. Sign up at https://dashboard.daily.co/
  2. Get API key from Developers section
  3. Set in .env.local:
     NEXT_PUBLIC_VIDEO_PROVIDER=daily
     DAILY_API_KEY=xxxxx

Step 2: Test Video Room Creation
  1. First create a booking
  2. POST http://localhost:3000/api/integrations/videocall/create
  3. Headers: Authorization: Bearer [your-token]
  4. Body:
     {
       "bookingId": "[booking-id]",
       "duration": 60,
       "recordingEnabled": true,
       "maxParticipants": 10
     }

Expected Response:
  - Status: 201
  - Response contains:
    {
      "success": true,
      "videoRoom": {
        "roomId": "...",
        "roomUrl": "https://...",
        "provider": "daily",
        "expiresAt": "2024-..."
      }
    }

Step 3: Test Video Room
  1. Copy roomUrl from response
  2. Open in browser
  3. Test video/audio connection
  4. Invite participant by sharing URL

Expected: Video call works, both can see/hear each other


3.3 ANALYTICS (Google Analytics 4)
───────────────────────────────────

Step 1: Setup Google Analytics
  1. Go to https://analytics.google.com/
  2. Create GA4 property
  3. Get Measurement ID (starts with G-)
  4. Set in .env.local:
     NEXT_PUBLIC_GOOGLE_ANALYTICS_ID=G-XXXXXXXXXX
     GOOGLE_ANALYTICS_API_SECRET=xxxxx

Step 2: Test Analytics Event Tracking
  1. POST http://localhost:3000/api/integrations/analytics/track
  2. Body:
     {
       "eventName": "test_event",
       "userId": "user123",
       "properties": {
         "page": "/bookings",
         "action": "create"
       }
     }

Expected Response:
  - Status: 200
  - Message: "Event tracked successfully"

Step 3: Verify in Google Analytics
  1. Go to GA4 Dashboard
  2. Wait 30 seconds to 2 minutes
  3. Go to Real-time > Events
  4. Look for "test_event"

Expected: Event appears in real-time events


3.4 ERROR MONITORING (Sentry)
──────────────────────────────

Step 1: Setup Sentry
  1. Go to https://sentry.io/
  2. Create account and project (select Next.js)
  3. Get DSN
  4. Set in .env.local:
     NEXT_PUBLIC_SENTRY_DSN=https://xxx@xxx.ingest.sentry.io/xxxxx
     NEXT_PUBLIC_APP_VERSION=1.0.0

Step 2: Test Error Reporting
  1. POST http://localhost:3000/api/integrations/errors/report
  2. Body:
     {
       "errorName": "TestError",
       "errorMessage": "This is a test error",
       "userId": "user123",
       "email": "test@example.com",
       "page": "/dashboard",
       "level": "error"
     }

Expected Response:
  - Status: 201
  - Response contains eventId

Step 3: Verify in Sentry
  1. Go to Sentry Dashboard
  2. Look for "TestError"
  3. Check error details, user info, breadcrumbs

Expected: Error appears with all context

SECTION 16: TROUBLESHOOTING
================================================================================

16.1 COMMON ISSUES & FIXES
──────────────────────────

Issue: "Calendar integration not configured"
Fix: Check GOOGLE_CALENDAR_* variables are set

Issue: "Video call service not configured"
Fix: Check NEXT_PUBLIC_VIDEO_PROVIDER is set

Issue: "Unauthorized" error
Fix: Add Authorization header with valid Bearer token

Issue: "MONGODB_URI not found"
Fix: Check .env.local has MONGODB_URI

Issue: "API rate limited"
Fix: Wait 60 seconds or check rate limit logic

Issue: "Email not sending"
Fix: Check SMTP credentials are correct

Issue: "Payment fails"
Fix: Check Stripe/Razorpay credentials and test mode

Issue: "Build fails with TypeScript errors"
Fix: Run: npm run build -- to see full errors
